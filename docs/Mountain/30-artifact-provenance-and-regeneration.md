# 关键资产溯源、预览与局部再生成需求

状态：已记录，待拆分实施
来源：用户于 2026-09-06 明确提出的产品需求

## 原始意图

`outputs/` 中每个任务生成的声音、图片、视频等关键资产，必须保留与该资产一一绑定的 JSON 生成结构。任务队列要让用户直接预览每张图片、每段声音和视频；结果不满意时，可从资产上的浮动隐藏入口查看生成配置，修改提示词或其他参数后手动再次生成，并用成功的新结果替换当前资产。

## 产品契约

1. 每个关键资产必须同时存在可解析的生成记录。记录至少包含稳定 `asset_id`、资产类型、任务/运行/阶段/单元标识、当前 revision、输入资产引用、完整输入参数、正向与负向提示词、Provider/模型与可公开配置、随机种子、输出相对路径、内容类型、校验和、创建时间和生成状态。
2. Secret、Authorization header 和完整凭据不得进入生成记录、前端响应、日志或诊断包；记录只保存服务 ID 和非敏感配置。
3. 资产文件与生成记录必须使用项目相对路径，并位于同一任务的 `outputs/<task-id>/` 边界内。JSON 不能引用项目外路径，也不能把临时绝对目录固化为可重放参数。
4. 任务队列和任务详情按类型提供图片预览、音频试听和视频播放。点击资产主体打开预览；鼠标悬停、键盘聚焦或触屏操作时显示“生成配置”入口，不能只依赖 hover。
5. 配置面板显示实际生成当前 revision 的 JSON，而不是由 UI 猜测或重新拼装。用户可编辑允许修改的提示词、输入参数和输出参数；系统必须在运行前完成 schema、路径、能力和必填字段校验。
6. “再次生成”只重跑该资产所属的最小可执行单元，不自动重跑整个任务。请求必须携带当前 revision，防止多个页面并发覆盖。
7. 新结果先写入任务内临时位置，完成内容校验、类型校验和校验和计算后，再原子替换当前资产文件并递增 revision。失败或取消不得破坏当前可预览版本。
8. 产品语义是“新成功结果覆盖当前资产”；同时保留每次尝试的 JSON、状态、时间、错误摘要和父 revision，以便审计、比较和恢复。旧二进制是否长期保留由后续容量策略决定，但元数据链不得丢失。
9. 替换成功后，所有引用该资产的 manifest、下游失效状态和前端缓存必须同步更新；依赖旧内容的下游结果应明确标记为待重新生成，不能继续显示为最新成功结果。

## 建议的任务内结构

```text
outputs/<task-id>/
└── runs/<run-id>/
    └── assets/<asset-id>/
        ├── current.<ext>
        ├── generation.json
        └── attempts/<attempt-id>.json
```

`generation.json` 是当前 revision 的权威记录；`attempts/` 保存每次手动或自动生成尝试的非敏感输入、结果与父 revision。具体 schema 名称可在实施时确定，但上述信息和行为不可省略。

## 最小验收标准

- 任取一个生成图片、音频和视频，均能从 API 返回的 `asset_id` 找到文件和匹配 JSON，校验和一致。
- 队列中三类资产均可预览，配置入口支持鼠标、键盘和触屏。
- 修改提示词后只触发目标资产再生成；成功后 revision 增加、当前预览更新、旧请求并发提交被拒绝。
- Provider 失败、取消、无效输出或进程中断时，原资产保持可用且 JSON 记录失败尝试。
- 生成记录和诊断导出中不出现 Secret 或项目外绝对路径。
