# PR 需求定义：语义分段配音与精确音画同步

## 状态与决策

- 状态：待评审
- 目标版本：待排期
- 适用模式：标准制作、自定义参考
- 不在本 PR 范围：动态信息图模式（已有 Whisper 词级时间轴）

## 背景

当前标准制作的配音与画面采用“整篇配音优先”的流程：全文生成一个 `voice.wav`，读取其总时长后，后端再将文案拆成场景，并按场景文本长度比例分配 `duration_ms`。因此总成片时长与配音一致，但场景切换点是估算值，不保证与实际说到的原文边界一致。

这会造成一个产品层面的缺口：用户希望看到的是“说到这个观点时，出现对应画面”，而当前实现只能做到“整段旁白结束前，所有画面大致按文案顺序出现”。文案越长、句子语速差异越大，误差越明显。

## 问题陈述

需要把标准制作和自定义参考从“全文音频 + 事后估算场景时长”改为“先规划语义音画单元，再以每个单元的真实音频时长驱动画面”。

核心目标不是把一个长 WAV 文件机械拆开，而是让每个画面都有明确、可追溯的原文范围和对应的真实旁白音频范围。

## 术语

| 术语 | 定义 |
| --- | --- |
| 音画单元（AV unit） | 最小可播放单元：一段原文、一段独立 TTS 音频、一张主要图片、一个视频片段。 |
| 语义段（section） | 文案中的一个自然段、话题或完整观点；可由 1–2 个音画单元组成。 |
| 母带 | 所有音画单元音频按顺序无损/无感拼接后的 `voice.wav`，供下载、历史兼容和最终合成使用。 |
| 清单（manifest） | 记录单元顺序、原文范围、文件、真实时长、累计偏移、状态和哈希的持久化 JSON。 |

> 精确同步的必要约束：默认必须是 **1 个音画单元 = 1 段音频 = 1 张主要图片**。一个语义段可以有 1–2 张图片，但若有 2 张，必须拆为 2 个各自有原文与音频的音画单元；不能让两张独立叙事图片共享一段未经对齐的音频后再按字数估算切换。

## 目标与非目标

### 目标

1. 图片/场景切换点与对应旁白片段的起止边界一致。
2. 长文案可由多个可恢复的音画单元组成，不因一次超长 TTS 请求失败而从头重做。
3. 最终仍输出一条连续 MP4，并保留兼容现有后处理与历史任务的 `voice.wav`。
4. 单元按自然语义和句末停顿切分，避免固定字符数硬切。
5. 任务取消、失败重试、重启恢复均能定位到单元粒度。

### 非目标

1. 本 PR 不承诺标准白板模式的逐字/逐词元素动画同步；它保证的是音画单元边界准确。逐词精度需要后续引入 ASR/Whisper 对齐。
2. 不重构信息图的 Whisper 时间轴与 Remotion 渲染路径。
3. 不支持用户直接上传已拆分的配音片段。
4. 不在此 PR 中实现跨单元语气连续性模型；仅通过自然语义切分、音频规范化与边界质量控制降低突兀感。

## 现状与差距

| 当前环节 | 当前行为 | 对需求的影响 |
| --- | --- | --- |
| 配音 | `voice_stage()` 对完整 `copy` 单次调用 `synthesize_voice()`，生成 `voice.wav` | 单次失败重做全文；没有原文到音频片段的映射。 |
| 分镜 | `make_plan()` 在得到总音频时长后规划场景 | 分镜可表达语义，但场景时长依赖全局估算。 |
| 时长 | `fit_scene_durations()` 以文本字符数比例填充各 `duration_ms` | 总时长准确，单场景边界不准确。 |
| 字幕 | 标准模式将场景时长按字幕文本长度再次估算 | 两层估算，长视频累计误差加大。 |
| 渲染 | 每个 board 可生成独立 MP4，随后合并，再与单一 `voice.wav` 合成 | 视频分段已有基础，但音频和画面没有一一绑定。 |
| 恢复/重渲染 | 以是否存在 `voice.wav`、`plan.json`、图片为主要检查点 | 无法只恢复失败的配音片段。 |

当前相关实现位置：`webapp/server.py` 中的 `voice_stage()`、`make_plan()`、`fit_scene_durations()`、`write_subtitles()`、`render_generated_job()`、`enqueue_job_from_checkpoint()` 和 `create_rerender()`。

## 目标数据流

```text
全文文案 + 参考音频 + 风格设置
  │
  ├─ 1. 语义规划（先于配音）
  │      → sections / AV units：每个单元保留原文范围、画面意图与图片提示词
  │
  ├─ 2. 顺序生成每个单元的 TTS 音频
  │      → voice-001.wav、voice-002.wav ...（读取每段真实时长）
  │
  ├─ 3. 写入 voice-manifest.json，并累计全局时间偏移
  │      → 拼接为兼容母带 voice.wav
  │
  ├─ 4. 每个 AV unit 生成对应图片和白板视频
  │      → scene-001.png + scene-001.mp4 ...
  │
  ├─ 5. 基于 manifest 的真实偏移生成字幕与视频拼接清单
  │
  └─ 6. 合成 final.mp4
```

## 功能需求

### FR-1：先进行语义音画规划

1. 在调用 TTS 之前生成并持久化 `av-plan.json`。
2. 规划器必须覆盖用户原始文案，不得遗漏、重排或改写作为旁白输入的原文。
3. 每个 AV unit 至少包含：`id`、`text`、原文字符范围、所属 section、画面意图、图片提示词、顺序号。
4. 切分优先级：自然段 > 明确话题转换 > 完整句末标点；不得在词内、数字/日期内、引号未闭合处切断。
5. 对异常超长句，规划器可在逗号、分号、顿号后的语义完整处切分，并记录 `split_reason`。
6. 每个 section 默认包含 1 个 AV unit；仅当语义明确有两个连续观点时允许拆为 2 个 AV unit。

### FR-2：分片配音与母带

1. 每个 AV unit 独立调用当前配置的 IndexTTS 节点，产出 `voice-<序号>.wav`。
2. 同一任务内的语音单元必须顺序执行；不同任务仍按现有语音节点数量并发，防止长任务把队列拆成大量子任务后抢占全部资源。
3. 每个片段落盘必须使用 `.partial` 临时文件，校验有效时长后原子替换为正式文件。
4. 所有片段必须标准化为一致的采样率、声道、编码和容器后拼接。默认不添加人工静音；若产品后续提供停顿策略，停顿必须作为 manifest 时间的一部分。
5. 所有单元完成后生成连续 `voice.wav`；该文件是最终合成和旧流程兼容所需的母带。
6. 音频连接处必须记录检测结果（格式一致性、首尾静音、响度差）；发现明显异常时任务应给出可理解的告警或失败信息。

### FR-3：以真实时长驱动画面

1. 每个 AV unit 的 `duration_ms` 必须来自对应 `voice-xxx.wav` 的实际探测结果，而不是字符数估算。
2. 该单元的白板视频时长必须等于对应音频时长，沿用现有 `valid_timed_video()` 校验思想。
3. 视频拼接顺序必须与 manifest 顺序完全一致；最终音画合成应使用母带。
4. 标准字幕应依据 manifest 的累计 `start_ms/end_ms` 生成；一个 AV unit 内可按现有句子规则生成子字幕，但不得越过单元边界。
5. 图片提示词、任务详情页和图库均须能反查对应 AV unit 的原文。

### FR-4：恢复、重试与失效规则

1. `voice-manifest.json` 是配音恢复的唯一权威来源；不再仅通过 `voice.wav` 是否存在判断配音阶段完成。
2. 某一片段失败后，重试只重新生成该片段；已完成片段不得重复调用 TTS。
3. 若修改任一 AV unit 的旁白文本，必须使该单元及其后的累计偏移、母带、字幕、视频合并产物失效；默认使整条视频重新渲染，避免时长变化导致后续同步错误。
4. “重新手绘”不重做配音；它继续消费既有 manifest 和母带。
5. 老任务没有 manifest 时继续走旧的单 `voice.wav` 路径，并在 UI 中标记为“旧版估算同步”。

## 建议的数据契约

`voice-manifest.json` 示例：

```json
{
  "schema_version": 1,
  "timing_mode": "semantic_audio_units_v1",
  "source_copy_sha256": "…",
  "master": {"file": "voice.wav", "duration_ms": 48200, "sha256": "…"},
  "units": [
    {
      "id": "unit-001",
      "index": 1,
      "section_id": "section-001",
      "text": "第一段完整原文。",
      "source_range": {"start": 0, "end": 9},
      "split_reason": "paragraph",
      "voice_file": "voice-001.wav",
      "duration_ms": 6200,
      "start_ms": 0,
      "end_ms": 6200,
      "status": "done",
      "audio_sha256": "…",
      "image_file": "scene-001.png",
      "video_file": "scene-001.mp4"
    }
  ]
}
```

`plan.json` 可逐步迁移为引用同一 `unit_id`，但本 PR 不应同时废弃旧场景字段。迁移期至少应在场景对象中写入 `unit_id`、`start_ms`、`end_ms` 和真实 `duration_ms`。

## 对当前 Web UI 的影响

### 必须改动

| UI 区域 | 当前行为 | 目标改动 |
| --- | --- | --- |
| 文案输入提示 | “按口播节奏自动拆分场景” | 改为“先按语义拆分旁白与画面单元；每段旁白对应一个主要画面”。 |
| “每张图包含几个分镜” | 控制 `scenes_per_image=1..4`，容易误解为多段文案共用一张图 | 在精确同步模式下替换为“画面节奏”：默认“每段旁白 1 张主图”；可选“一个章节 1–2 个连续音画单元”。不能保留“每张图 4 个分镜”作为精确同步选项。 |
| 制作步骤 | 先“克隆参考音色”，后“拆分文案分镜” | 改为“规划音画单元 → 分段克隆音色 → 生成插图 → 绘制并拼接 → 合成”。 |
| 进度卡 | 只显示幕数、图片数与总时长 | 显示“配音单元 N/M”“当前单元”“已生成母带”；失败时显示可重试的单元编号与原文摘要。 |
| 历史详情/图库 | 图片只对应场景编号和提示词 | 展示每张图片的原文、对应音频时长、全局播放区间和同步状态。 |
| 重新生成图片 | 仅按页面编号重生成图片 | 保持“仅改图不改音频”；必须提示此操作不改变旁白和画面起止时间。 |
| 历史旧任务 | 未区分同步质量 | 标识“旧版估算同步”，但仍可观看、下载和重绘。 |

### 建议新增的用户设置

设置应保持少而明确；不把 TTS 的技术限制直接暴露给普通用户。

| 设置 | 位置 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 音画同步方式 | 制作设置 | `精确分段同步` | 新任务默认使用本 PR 流程；保留 `兼容估算同步` 仅用于回退、故障排查或历史复现。 |
| 画面节奏 | 制作设置 | `每段旁白 1 张主图` | 可选“章节内 1–2 个连续音画单元”；该选项改变规划粒度，不允许一段未对齐音频对应两张图。 |
| 分段计划预览 | 提交后/规划阶段 | 开启 | 显示单元序号、原文摘要、预计画面意图；第一版只读，后续可扩展为用户合并/拆分。 |
| 语气连续性提示 | 配音设置说明 | 开启 | 在多段模式说明“系统将优先在自然停顿处分段；段落开头的语气可能略有差异”。 |

### 不建议暴露给普通用户的设置

- 每段最大字符数、最大秒数；应作为服务端运行配置，依据 IndexTTS 模型能力设定。
- 音频采样率、声道、拼接编码与响度参数；应固定为系统兼容策略。
- 语音队列并发数；这是全局资源治理设置，不应由单个任务改变。

## 后端与数据层改造清单

| 模块 | 必需改动 |
| --- | --- |
| 任务模型 | 增加 `timing_mode`、`audio_unit_count`、`audio_units_completed`、`current_unit_id`、manifest 版本、同步状态与告警。 |
| 规划 | 将现有“配音后 `make_plan()`”拆成“配音前语义 AV 规划”与“配音后写入真实时长/累计偏移”两阶段。 |
| 语音队列 | 保持任务级调度；在 `voice_stage()` 内顺序处理单位音频，或引入带公平性的子任务调度器。 |
| TTS 适配器 | 复用 `synthesize_voice()` 的协议适配与重试，但增加片段命名、原子写入、幂等检查。 |
| 音频处理 | 新增 WAV 规范化、拼接、母带校验和连接处质量检测。 |
| 分镜/图片 | 场景与 AV unit 建立一对一引用；图片提示词只使用该单元原文和必要的全局上下文。 |
| 视频渲染 | 以每个 unit 的真实 `duration_ms` 渲染；标准路径的 board 分组逻辑需迁移或仅作为同一画面内的装饰布局。 |
| 字幕 | 使用 manifest 偏移替换跨场景字符比例时长；后续可接入单元内 ASR 对齐。 |
| 恢复 | `enqueue_job_from_checkpoint()` 读取 manifest，跳过完成的片段，重建缺失母带或下游产物。 |
| 重渲染 | `create_rerender()` 复制 manifest、母带和必要图片；不得要求重新配音。 |
| 兼容 | 旧任务维持 `standard_v1` 分支；新任务使用新的 pipeline/timing 版本，禁止错误混用检查点。 |

## 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 片段首尾语气不连续 | 成片听感变差 | 仅在自然停顿处分段；记录并检测首尾静音；先小范围验证 IndexTTS 输出。 |
| TTS 调用次数增加 | 总请求开销和失败点增加 | 单元级重试/恢复；任务内顺序执行；只对超过阈值或启用精确同步的任务启用。 |
| 图片生成量增加 | 成本与等待时间增加 | 默认 1 张主图/单元；规划器按内容密度合并短句，但不能破坏音画单元边界。 |
| 规划模型遗漏或改写原文 | 配音与用户文案不一致 | 使用原文范围和覆盖率验证；合成 TTS 输入必须直接来自原文切片。 |
| 拼接格式不兼容 | 音频断裂或合成失败 | 在拼接前统一 PCM 参数；母带生成后 ffprobe 校验总时长。 |
| 旧检查点误复用 | 时长错位 | 新 pipeline/timing 版本隔离文件名与校验逻辑。 |
| 超长任务垄断队列 | 其他用户排队时间恶化 | 保留任务级公平调度；设每轮单位数配额或在单元边界重新排队。 |

## 分阶段实施建议

### Phase 1：可靠的单元级边界

- 仅标准制作模式。
- 自动语义规划，每个 AV unit 对应一张图和一段音频。
- 顺序 TTS、manifest、母带拼接、真实时长渲染。
- UI 展示单元进度与历史原文映射。
- 不提供用户手工编辑分段计划。

### Phase 2：可控性与恢复完善

- 自定义参考模式接入。
- 单元失败重试按钮、只读分段计划详情。
- 旧任务/新任务的同步模式标识。
- 任务重启后的完整 manifest 恢复测试。

### Phase 3：更细粒度同步

- 可选的单元内 Whisper 对齐。
- 高精度字幕与关键元素按词/短语入场。
- 允许用户在生成前合并或拆分单元，并定义受影响产物的精确失效范围。

## 验收标准

1. 新建标准任务产生 `av-plan.json`、`voice-manifest.json`、多个 `voice-xxx.wav` 和连续 `voice.wav`。
2. 任一 `scene-xxx.mp4` 的时长与其 manifest 单元 `duration_ms` 的差异不超过现有视频校验容差。
3. 母带时长等于所有单元音频时长（含明确记录的人工停顿）之和；最终 MP4 音视频时长一致。
4. 删除或损坏第 N 段音频后重试，仅会重新调用第 N 段 TTS；前 N-1 段不会重新生成。
5. 文案长度显著超过单次 TTS 推荐限制时，任务仍能完成，且队列中其他任务不会被其所有分片一次性挤占。
6. 每张生成图片在历史详情中可显示对应原文、音频文件、真实时长及全局起止时间。
7. 旧任务可继续下载、重绘和恢复，不会被当成新 manifest 任务处理。
8. 标准模式不再调用 `fit_scene_durations()` 为新精确同步任务分配场景时长；该函数只服务旧版兼容路径或明确标记的估算模式。
9. 自动测试至少覆盖：规划覆盖率、manifest 偏移累加、片段失败恢复、母带拼接、取消后的不再调度、旧任务兼容、最终 A/V 时长一致。

## 待确认项

1. IndexTTS 在目标部署环境中的安全单请求文本上限、最佳片段时长和输出 WAV 格式。
2. 是否默认对所有新标准任务启用精确分段同步，或先作为 Beta 开关发布。
3. 允许的最长任务时长、最大 AV unit 数、最大图片数及对应成本/配额策略。
4. “章节内 1–2 个连续音画单元”是否需要在首版开放，还是首版固定为 1 个 AV unit/语义段以优先验证质量。
5. 是否接受在第一版保留“单元内字幕按句子规则估算”，或必须同时交付单元内 ASR 对齐。
