# CS Board 团队学习策略

- 用户是产品使用者和最终体验验收者，不承担接口补全、测试夹具或工作单修复。
- 正常目标是 2–3 轮内通过审核，不强求一次通过。
- PM 在审核关闭时记录原子反馈：触发条件、候选改进、证据路径、角色和任务。
- 单次事件置信度为 0.3；重复或独立复现后才提高。
- 只有同类问题重复出现，且新的模板、脚本或指令经回放证明有效，才修改项目级 Skill。
- 只有跨项目证据或用户明确决定，才把项目规则提升到 POS 全局 Skill。
- 不在学习记录中保存密钥、用户文案、参考音频、生成媒体、源码片段或大段日志。
- 里程碑结束时评估：审核轮次、重复缺陷率、错误通过声明、范围泄漏、环境阻塞和模型升级次数。
